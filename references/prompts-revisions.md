# LibTV Prompt 与局部修改模块

模块选择与共同协作方式见 [模块总览](../SKILL.md)。

## 1. 什么时候使用

用户需要资产生成、镜头图、视频或声音的提示词，或带着原 Prompt、截图、素材和反馈回来修改时使用。只要本次意图足够清楚，就从当前材料开始；不要求补 Logline、完整剧本或进度日志。

本模块负责把已经明确的画面、动作与声音设计变成可执行的生成说明，不擅自改写故事。需要补镜头设计时按需使用 [分镜与导演模块](storyboard-direction.md)，需要定义角色、场景、道具或声音参考时按需使用 [资产与声音模块](assets-sound.md)。用户要求一并完成，就在同一份交付中完成，不把模块变成审批关卡。

剧本确定后继续制作时，按 [完整制作指南](complete-word-guide.md) 在一份 Markdown 文件内给齐全部必要资产 Prompt 与逐镜关键帧、视频和音频生成指令。用户明确要求 Word／`.docx` 时再按指定格式导出。这里的局部交付形式只适用于明确的单项请求，不用它把完整指南重新拆成多轮。

## 2. 先分清这次生成什么

| 任务 | Prompt 重点 | 不混入什么 |
|---|---|---|
| 角色、场景、道具等静态资产 | 可辨识外形、材质、必要视角、状态、背景与光影；已有参考的保留项和变化项 | 一连串动作、剪辑顺序、无关剧情说明 |
| 本镜关键画面，包括首帧与目标尾帧 | 每帧为独立静态单图：人物站位、视线、构图、光向、道具位置，以及对应起始或结束的动作瞬间 | 同时描述动作前、中、后三个不兼容姿态，或将首尾两帧合成对照图 |
| 视频 | 起始状态、关键动作与反应、镜头运动、结束状态，以及本次需要的声音 | 在已有参考之上反复重造角色身份，或只写静态美术词 |
| 配音、音效、音乐 | 台词与表演，或声源与事件，或音乐情绪与发展；按任务分别写 | 把表演指令读进台词，把音色示例当成最终对白 |

文字先描述可看见、可听见的结果。形容词、摄影术语与器材描述只有确实帮助表达时才保留；不靠质量后缀、万能负面词或超长前缀承诺好效果。

人物小传按 [资产模块](assets-sound.md) 转成外形与行为依据：静态角色 Prompt 写稳定身份和本次造型，不整段粘贴身世、善恶标签或未来剧情；视频 Prompt 写本镜真正发生的行为与声音。分镜表里已写明的关键动作、对白与声源，要落实到可复制正文，不能只留“人物自然微动”等概括。实际需要随视频生成的台词写清谁说、说什么；内心独白注明为画外声音，不让角色据此对口型。计划独立配音的内容另行给齐，不误要求视频重复生成。

## 3. 参考关系先讲清，复制内容要完整

- 每份参考说明用途：人物身份、场景空间、道具细节、构图、姿态、运动路线、风格或音色。出现冲突时说明哪个特征以哪份为准。
- 用当前真实存在的图片名称、上传顺序或节点名指认参考；只有取得实际 ID 且当前工具支持时才写节点引用语法。不捏造 ID，不把说明标签当成自动绑定。
- 用户尚未提供参考时，写明这是待连接的输入，并给出可先生成它的说明；已有足够条件的部分继续交付，不卡住整个项目。
- 全局风格和人物资料可以在工作文档中只维护一份；但每条给用户独立复制的 Prompt，必须带上这次生成必需的信息。不要写“同上”“详见全局设定”后就假设模型会读取其他文件。
- 有可靠参考时重点描述本次变化，不重复整张资产卡；参考缺失或不负责某个关键特征时，把该特征补进文字。精简与详写都以表达充分为准，而不是为了省字牺牲效果。
- 画外人物保留影响本镜的视线目标、对白、声音、接触或后续衔接状态；没有这些作用时，不逐镜重述其完整服装与资产说明。独立复制仍须自足，不能以省略重复为由丢掉必要的空间关系或身份依据。
- 标注图中的箭头、圈选、文字用于说明布局或修改目标，不是作品本身；需要时明确成图不保留这些标记。

### 多人同框：身份、视线与视觉重点

人物串位、服装串用、视线落错目标，或多人画面难以读懂时使用。补强现有参考分工，不新增用户必填表、逐张审批或通用禁令。

- **人名不是外形参考。** 将本镜需要区分的人物写成“身份／称呼＋必要可见特征＋画面位置＋动作／持物”。已有角色图时说明真实输入对应，确认执行工具实际传入；名字、文件名或摘要中的标签本身不构成绑定。只补有助于区分的特征，不重复小传，也不靠凭空改脸、加伤疤区分角色。剧情中的同貌、双胞胎或身份互换按原设定处理。
- **动作和物件有明确归属。** 同框多个人时少用含糊的“男人”“他”“另一人”；关键持物、交接或表演直接落到指定人物。左右手、道具状态优先沿用已确认画面或文本；交接时写清动作阶段，不为补完整而擅改已确认剧情。
- **视线要在当前机位下读得出来。** 分清人物站位、身体／头部朝向、目光目标，以及摄影机从哪里看。目标入画就交代它与人物的位置关系；画外目标说明实际空间方向，必要时借邻镜建立，不强行全部塞进同框。目标与另一人物在画面中重叠、或表情与朝向难以同时表现时，先调整机位／站位或按需拆镜；“看向那里”或“目光越过某人”不能独自解决遮挡与投影歧义。
- **构图服务当前剧情重点。** 先确定观众本镜需要读到谁的什么反应，再安排前景占幅、遮挡、焦点和主次亮度。前景肩背不是越大越有电影感，关键反应也不一定都在正中央。压迫感、隐藏信息等有意遮挡可保留；不把所有人同时清晰、明亮作为通用标准。
- **静帧写此刻姿态，视频写变化过程。** 静帧不把“抬头、转身、看向、递出”全过程塞进一张图；视频再说明变化的触发、路径和终点。参考图的虚焦肩背、裁切和遮脸排版不替代角色身份参考。

**可复用底稿**（由模型按已有材料填实、合并成自然语言；不把空槽、填写说明或内部检查项交给用户）：

```text
输入与参考：实际使用的每张图片及其职责；人物外形、场景空间、编辑底图分别指认。尚未提供的输入明确标为待准备，不声称已绑定。

画面正文：
[摄影机所在位置、景别与本镜需要读清的反应／信息]。
[人物甲的身份和关键外形]在[位置]，处于[姿态／持物状态]；[人物乙的身份和关键外形]在[位置]，处于[姿态／持物状态]。只写实际出镜且有作用的人物。
[指定人物]的头部／身体朝向[方向]，目光落向[具体目标及空间位置]；[让此关系可读的机位或构图安排]。
[前景、主体与背景的可见范围、焦点和主次亮度]；光源来自[已有场景中具体位置]，保留[有助于叙事的受光和层次]。

用于视频时，把静态状态扩写为本镜实际动作过程，声音按“视频声音字幕与模型适配”处理；用于静帧时只描述目标瞬间。
```

**自写示例：展厅三人镜头。** 假设输入已实际连接：图 1 为深色西装策展人，图 2 为白衬衫、靛蓝围裙修复师，图 3 为绿色外套访客，图 4 为展厅空间图。展厅图已确认后墙左侧有一幅待介绍的装框画。本镜要让观众读懂“访客关注画作而非修复师”；这些设定仅用于说明写法，不覆盖用户故事。未连接这些参考时先补输入说明，不直接声称已经具备。

```text
生成一张 16:9 展厅静态镜头图。人物外形分别对应图 1 的深色西装策展人、图 2 的白衬衫靛蓝围裙修复师、图 3 的绿色外套访客；展厅布局与后墙画作沿用图 4。

摄影机位于策展人身后偏右，以侧后方中全景拍摄。策展人的虚焦肩背留在画面左下边缘。修复师位于中景偏左，手持合拢的红色文件夹，面部朝向右侧访客。绿色外套访客位于画面右侧，身体斜向后墙，头部转向后墙左侧的装框画，呈侧后方姿态。

构图让装框画落在修复师右肩之外的可见空隙中，访客至画作的视线方向与修复师位置错开；访客的头部朝向和目标画作都是本镜需要读清的信息，不追求正面脸部特写。策展人的肩背不遮住访客或画作，修复师仍保留可辨认的围裙与文件夹。

沿用展厅顶灯和画作上方射灯的位置。画作与访客转向画作的一侧获得清楚受光，前景肩背较暗，背景保留展厅深度；景深服务人物朝向与目标画作的可读性，不把画作虚化成无法辨认的色块。输出一张场景画面，不带参考图编号或构图标记。
```

该示例未经实际生图验证；其机位与摆位也需对照真实场景参考检查。不是“写上视线错开就保证模型照做”。

**返修模板：**“以[已查看的待修图]为底图，[正确人物、位置、场景、光源等]保留；依据[实际连接的对应人物参考]将[明确位置的人物]校正为[目标身份与外形]，保留／调整[原持物与动作状态]；若修视线，明确[目标与构图修正]。允许改动引起的局部遮挡、投影和反光同步变化。”只改实际错误；身份和整体站位同时严重错误时，回到正确参考重建，不把局部修复当万能方法。

看结果时先核对“谁在何处、谁做什么／持什么、看向谁／哪里、关键反应是否可读”，再讨论质感。区分已观察的错误与原因推测；只有 Prompt 摘要时不声称已查明完整输入或工具绑定。发现问题先修对应信息，不惯性追加整串禁用词。这里是一次轻量读图与定向修正，不增加循环评审程序。

### 先判定图片职责，再决定是否作为首帧

先按 [图片职责与首尾帧用途](assets-sound.md#图片职责与首尾帧用途) 区分实际选定尾帧、动作首帧与视觉参考；概念图不自动锁定开场，目标尾帧不冒充实得帧。

转写视频 Prompt 时，动作首帧衔接其正在发生的动作；视觉参考只继承指定要素，摄影机按本镜任务建立开场。没有尾帧输入也要描述所需结束结果。实际未连接、未生成或目标模型不支持的帧，不写成已生效的输入约束。

需要的静帧按资产模块分别写成单图指令，只描述单一动作瞬间；已有合适图就复用或局部修改。完整指南中的帧图 Prompt 集中在对应逐镜节，资产清单只索引；局部请求则在本次结果中完整交付。

## 4. 视频动作与镜头如何写

把动作写成有方向、有结果的过程：谁从哪里开始，什么触发了变化，身体或物件怎样移动，对方或环境怎样反应，最后停在哪里。接触或交接动作写清哪只手、物体哪一面、碰到或没有碰到，不只写“自然互动”。只补与镜头有关的细节。

区分人物在画面里的位置与他看向的目标。同框时可写“画面右侧的人转眼看向同镜左侧的人”；目标确在画外时，写清它在场景中的方向、远近及必要的视线高度。不要同一镜既要求某人清晰入画，又把他写成画外目标。换机位后按新的投影判断左右，沿用世界中的站位；机位移动或人物移动确实改变画面关系时，写出变化过程。

分镜若依靠同框展示双方回应，Prompt 就保留双方与关键动作可见的构图；若依靠局部反应，明确观众需要看清哪一个变化。不要在转写时把它们统一简化成“人物说话”或泛用的推近特写。

运镜说明起点、运动方式、方向、节奏、终点与要看到的信息。区分相机原地转动、机身移动和镜头变焦；需要安静观察时可以固定机位。不要同时给出互相抵触的固定、环绕、推近等指令。

一条生成任务可以按当前能力承载一个镜头或多个镜头，但它不等于整片分镜表里的一个固定单位。连续运镜段落不写成多次硬切；多个剪切镜头则明确顺序。动作复杂时可以设计关键帧、连续分段或剪辑接力，保留创作意图，不默认砍掉有价值的动作。

需要时间标记时，每个独立生成任务从本地 0 秒开始；整片位置另写在分镜表中。只在有助于动作和对白安排时划分时间，不机械逐秒填满。计划时长不等于素材实得时长，已有配音时以实际声音及停顿来安排。

### 按镜头类型调节约束密度

Prompt 只控制会显著改变叙事、身份或动作因果的内容，其余空间留给模型完成自然运动。对白、交接、多人身份和关键道具镜头，可以较明确地写站位、动作归属、接触阶段与结束状态；追逐、爆炸、能量冲击等高动态奇观镜头，优先保留一条清楚的运动主线、一个主要摄影机关系和一次必要的节奏变化，不用逐秒塞满主体轨迹、粒子形态和机位微调。

高动态镜头如果同时要求摄影机离开原主体、追上高速对象、重新建立远端目标、改变观察轴线，并在撞击时从极速切入慢动作，先回到 [分镜模块](storyboard-direction.md) 判断是否拆成两个可执行镜头。保留单镜时，简化为一条有动机的摄影机接力，例如伴随主体加速、在撞击前自然减速停稳，再让动作继续完成；不要用更多限制掩盖视点跳变。

时间段只用于真正需要同步的对白、动作触发或明显节奏转折。高能镜头可以采用两三个宽松阶段和有力度的动作动词，让模型完成阶段内部的连续运动；不把“详细”误写成“每一秒都规定”。

### 视频声音字幕与模型适配

**共同制作目标：视频片段默认不生成背景音乐（BGM）和自动叠加字幕；保留本镜需要的对白、环境声与动作音效。** 单镜、多镜头生成、续接和局部返修共用这项默认，但不硬规定每个模型都在开头粘贴同一句否定指令。本节是声音、字幕默认与 Prompt 适配的主定义。

BGM 独立写音乐 Prompt，并在导演／剪辑说明里安排进入、退出和对白主次；音乐 Prompt 本身不套禁配乐要求。已定剧情中的演唱、收音机等有源声音保留其明确声源；剧情内招牌、信件、屏幕等文字也不等同于自动字幕。没有对白的镜头不新增对白，安静镜头不凭空补音效。用户明确指定视频内配乐或字幕时，只调整对应要求。

**先看当前 LibTV 模型、版本与实际入口，再选择表达。** 能力来自本次可见设置、可用官方工具或对应版本文档，不从品牌名、其他产品入口或旧画布推断。未核实的信息标为待核实，先交可用的自然语言内容，不编造输入框、参数或绑定语法。

| 当前已核实条件 | 交付方式 |
|---|---|
| 当前入口以自然语言接受这类限制 | 将“不要字幕，不要背景音乐（BGM），保留……”放入该条完整视频 Prompt，保留项按镜头填实；不要求一律放在开头 |
| 当前入口实际提供并支持独立负向字段 | 分开交“正向 Prompt”和“Negative”，明确各粘贴到哪里；Negative 只放相关排除项，需保留的声音写入正向或实际声音设置，不两边重复整段指令 |
| 对应模型文档建议正向描述、或不支持负向表达 | 把可表达的目标转为期望结果，如“画面保留干净的摄影构图”“声场由雨声、脚步和指定对白组成”；其余要求落实到已存在的字幕／声音设置或后期步骤，不把否定词换个位置当作适配 |
| 当前模型没有音频生成能力 | 视频正文聚焦画面；需要的声音在独立音频资产与剪辑说明中给齐，不要求该模型生成音轨 |

语言按用户要求与目标模型的已核实建议选择；需要英文时交一份可直接复制的英文 Prompt，中文保留用途和操作说明，不默认中英双份长正文。不把“英文一定更好”或“独立 Negative 必然更有效”当作通则；语言变化保留角色、动作、参考职责和声音意图，不顺便改剧情。

每条独立交付要自包含：采用单框时给完整正文；采用多字段或额外设置时，将该条的正文、Negative（仅支持时）与必要设置一起给齐，标清复制位置，不依赖文档别处的全局声明。若当前入口或输出音轨仍有生成不确定性，简短说明要检查实得结果；后期静音、重配音或混音按保留声音的需要选择，不承诺去掉 BGM 必成功，也不把混合音轨说成可无损拆分。

### 把光影意图写成模型能看见的变化

采用 [分镜模块的光影选择](storyboard-direction.md)，只补本镜缺少的信息：主要光从哪里照来、阴影怎样过渡、哪处细节要读清、主体和背景如何区分。有可靠关键帧时写清沿用的光影及本次变化，不重新堆一套布光术语；未提供相应参考时，把必要条件写进独立正文。不要用“柔光”代替所有明暗要求，也不把深影与均匀提亮同时写给同一张脸。

有动态光时，按已定事件写出“何时改变—照到什么—如何结束或延续”。人物走位引起的明暗变化与光源自身的变化分开描述；屏幕、车灯等产生的互动光按方向和距离影响附近人物或物件，不只让发光物单独闪亮。仍固定的光源继续固定，真实反射随机位变化，下一段只继承需要衔接的状态。不要为了展示灯光效果另造事件。

改光时明确保留人物身份、构图、服装与物体结构，并允许相应的投影、反光和受光颜色一起改变；别同时要求“重打光”和“所有阴影、高光完全不动”。这些句子融入原本的资产或视频 Prompt，不另交需要用户手动拼装的灯光后缀。

### 相邻片段的 Prompt 要能接力

按 [分镜模块的衔接设计](storyboard-direction.md) 将上一镜的收尾、下一镜的开场分别写进可复制正文。明确实际动作阶段、方向、持物状态或构图，不只写“承接上一镜”，也不让模型猜另一条 Prompt 的内容。

分开生成时，每条只描述该片段真正需要生成的画面和声音；不要为了两个文件之间的切换，在单条里追加“切到下一场”并意外生成额外场景。确实采用支持多镜头的一次生成时，才按当前能力写明内部切镜顺序。

需要遮挡、甩镜等生成内过渡时，把覆盖方向、运动过程和落点写在相应片段里；声音先入／延续、实际切点和叠化放到 Prompt 外的剪辑说明，不要求生成模型处理尚未输入的另一个文件。保留可调整的动作过程，避免统一冻结尾帧或强加片尾效果。

**动作衔接写法示意，不是完整生成 Prompt：**

- A 镜收尾：右手压下门把并开始推门，门逐渐打开，动作继续自然发展。
- B 镜开场：近景中右手已压住门把，门正在打开；从该动作阶段继续将门推开。
- 剪辑备注：在门开始移动的动作中切换景别，去掉重复的推门过程。换了机位就用对应的新构图，是否引用实际尾帧另按输入能力判断。

实际交付时，这些动作句直接融入各镜完整 Prompt，不另给用户一组需要自行拼接的“转场后缀”。只修一个镜头时保留邻镜满意内容；确有连带变化才指出。

## 5. 默认交付：用户知道复制哪段、参考怎么放

```text
用途：这一条生成什么。
输入与参考：连接哪些已有素材，每份负责什么；哪些输入尚未准备。

可复制 Prompt：
一段信息完整、顺序清晰的生成指令。

Negative：仅当前入口实际支持且本条需要时单独列出，并注明复制位置；其他情况省略。
设置提示：只列本次需要的比例、时长、生成方式等；与正文分开。
必要说明：仅交代会影响操作的前提，不附整套评审记录。
```

实际交付时填入完整内容，不把上述空模板原样交给用户；单框输入不输出一个虚构的 Negative 字段。Markdown 中用清楚的标题与独立可复制代码块；用户明确要求 Word 时，改用独立可复制文本段落，不把长 Prompt 塞进狭窄表格，不把 Markdown 围栏当成版式。用户只要 Prompt 时不增加无关讲解，但关键参考前提仍应讲清。

明确的模型选择、参考槽位、分辨率和时长范围按当前工具或对应版本资料核对，语言与负向表达按 [模型适配](#视频声音字幕与模型适配)。平台设置与正文分开；有已知设置时保持二者一致，未设定的“高清”或时长描述不冒充实际参数。

## 6. 用户不满意时，改真正的问题

先区分反馈来自观看结果，还是用户对文字的预演。没看过实际素材，就把原因说成推测；用户已经清楚描述问题时，可以直接修改，不强求先上传证据。

根据问题选择处理位置，没有固定先后顺序或重试次数：

| 问题更可能在哪 | 可以怎样处理 |
|---|---|
| 剧情、信息揭示或人物反应不合理 | 回到相关动作或镜头设计，说明修改理由；涉及核心剧情变化时先取得用户选择 |
| 人物、道具或场景参考混用 | 澄清参考职责、修正名字对应或补必要状态图 |
| 构图、朝向、局部元素有问题 | 用选定画面、圈选或路线标注做针对性调整，写明保留项 |
| 光影太平、重要细节太暗或颜色污染 | 先判断应改阴影可见度、主次亮度还是彩光范围；有意剪影不一律提亮，立体感不足不一律加硬光。回改相关设计或关键帧，保留满意身份与构图 |
| 动作、视线、接触或运镜不符 | 改写实际冲突的过程、路径和结束状态，必要时更换关键帧或分段实现 |
| 画面已可用，只是节奏、声音或清晰度有问题 | 优先判断选帧、剪辑、配音、混音或增强是否能解决，而非惯性重新生成 |

保留用户认可的内容；关联问题可以一起修，不为了“每次只改一个变量”拆成很多轮。给可直接替换的 Prompt 或具体操作说明，并仅在有影响时指出前后镜衔接的变化。

认为原方案更合适时，用观众会看到什么、信息会怎样变化来解释，避免术语堆砌或无条件附和。反复出现同一问题时重新判断方法，不机械增加形容词，也不未经授权自动继续生成。

## 7. 中途回来与续接

以用户最新提供的文件、截图、生成结果和描述为准；如果与旧记录冲突且会影响当前交付，只确认那个关键差异，不要求补齐全过程。

已有满意片段需要延续动作时，可说明从哪个选定帧继续，保留人物、视线、道具和光向的哪些状态；换场、跳时或需要新的信息时重新设计构图，不强制尾帧接尾帧。

用户只需要下一段 Prompt，就交下一段；只有下次衔接确实需要时才附一句“沿用哪些素材、下次带哪份结果”。不默认生成台账、审批卡或每轮进度摘要。

## 8. 自写示例：修改一个动作，不改整个场景

情境：修表铺柜台，顾客把停走的旧怀表推给师傅；师傅认出表背刻痕，伸手又停住。

用户反馈：“这里师傅的手碰到了怀表，我要的是快碰到前犹豫。”

回应要点：保留原构图、人物参考和光线，只把动作终点明确为接触前停住。仅凭文字反馈可以这样修改，不宣称已经确认实际失败原因。

输入：用户选定的本镜关键帧；其中怀表背面朝上，刻痕可见。若选定帧不满足这个前提，先给局部调整说明，而不是假设视频会自动修正。

**可复制 Prompt：**以下按接受自然语言限制、且支持本镜所需声音的入口示范；其他入口按 [模型适配](#视频声音字幕与模型适配) 转写。

```text
不要字幕，不要背景音乐（BGM），保留本镜的环境声与动作音效。

沿用参考画面的修表铺柜台、人物位置、旧怀表外形与光线。保持参考构图和固定机位，师傅的面部、柜台上的怀表和右手都在画面内。怀表背面朝上，表背刻痕保持可见。

师傅的右手从画面右侧缓缓伸向怀表；当指尖即将触到表背时突然停住，手指轻微收拢，维持停顿。停顿期间，指尖与表背之间保持清晰可见的空隙，没有触碰、按压或拿起怀表。怀表留在原处，师傅的视线仍停在表背上。结尾停在这段未完成的伸手动作上。

保留轻微衣袖摩擦声与修表铺环境底声。怀表已经停走，不为它添加走针声。本片段没有对白。
```

这是动作澄清示例，不是经模型试生验证的结果；实际素材好坏由生成后观察判断。若用户还有其他明确声音要求，一并保留，不用示例覆盖其原设定。
