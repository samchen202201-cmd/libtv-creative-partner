# 复用 Word 模板与生成器

仅在交付完整 Word 指南时读取。内容范围见 [完整指南](complete-word-guide.md)，不另开创作审批或重复编写排版代码。

## 生成方式

先完成内容稿，再将包内 `scripts/build_guide.py` 与 `assets/production-guide.docx` 配合使用。脚本按自身位置查找模板，整个 Skill 文件夹可以迁移；不依赖当前工作目录或私人路径。

在执行环境中解析 Skill 根目录、内容稿和输出文件的绝对路径，并使用可用的 Python 3 运行：

```sh
"$PYTHON" "$SKILL_DIR/scripts/build_guide.py" "$CONTENT_MD" "$OUTPUT_DOCX"
```

这些变量由执行者填入实际绝对路径，不是要求用户配置的步骤。在 Codex 中，先用依赖加载器取得 bundled Python 与文档工具；其他环境使用已有 Python 3 和 python-docx。只有依赖确实缺失时才说明，不为普通故事讨论安装文档依赖。

输出父目录需先存在。生成器保留原稿；同名文件存在时自动尝试 `_v2.docx`、`_v3.docx` 等递增名称，并在成功后输出实际文件路径。并发写入仍以独占创建防止覆盖；权限或磁盘错误会明确报错，不冒充重名继续尝试。它只负责排版，不生成故事或媒体，不联网，不安装字体。

## 内容稿语法

- `#` 为文档标题，`##` 为章节，`###` 为角色、资产或镜头标题。使用真实标题导航，不手写容易过时的页码目录。
- 普通段落、`**重点**`、`-` 清单和 `>` 简短提示均支持。独占一行的加粗标签会与下一段保持同页。
- 完整 Prompt 放在以三个反引号加 `prompt` 开始、三个反引号结束的代码块中。块内文本原样保留、可复制，不把操作说明混入 Prompt。
- `text`、`markdown`、其他标签及无标签代码块按通用文本块原样保留，采用灰底等宽样式，与 Prompt 样式区分；不执行代码、不再次解析块内 Markdown，也不自动认作生成提示词。中文、空行、缩进和代码符号均保留。块内含三个反引号时，可用四个或更多反引号包住；结束围栏至少与起始围栏等长。未闭合围栏、表格列数不一致等格式错误仍会报告位置，先修正文稿再生成。
- 概览使用 Markdown 表格。单元格内换行用 `<br>`，字面竖线写为 `\|`。不把长 Prompt 塞入多列表格。
- 表格前可写 `<!-- widths: 4,18,5 -->` 指定三列宽度，单位为厘米；列数必须对应，超出版心时等比缩小。按内容调整，不强求等宽。
- 仅在确有版式需要时使用 `<!-- pagebreak -->`；通常让正文自然分页。

生成器不是通用 Markdown 转换器。不要依赖四级标题、嵌套列表、图片嵌入或任意 HTML；当前指南默认以可复制文字交付。若用户要求图片版式或另一种模板，按其需求使用文档工具，不把这些格式当作已经支持。

## 默认版式与检查

模板为 A4 横向：紧凑首页、真实标题层级、暖棕表头、浅底色 Prompt 段落和页码。列宽可调整；用户有自己的版式要求时优先采用，不靠挤小字号或删剧情追求固定页数。

先看生成内容是否完整，再检查中文、表格、长 Prompt 与分页。存在 `documents` Skill 时按其渲染检查要求执行；具体缺陷定点修复，不因为做 Word 就重复重写剧本或启动额外创作评审。

模板默认使用 Hiragino Sans GB。跨平台预览可按以下顺序准备字体回退：Hiragino Sans GB → Microsoft YaHei → Noto Sans CJK SC → 系统默认中文字体。运行或预览环境应至少有一套可显示中文的字体；若预览缺字，先检查渲染器字体配置。字体回退只影响显示，不改变正文内容；不要在包里分发未经许可的字体文件。

## 模板样式

`assets/production-guide.docx` 内置以下自定义样式，生成器按样式名写入内容：

- `Guide Table`：表格正文与表头的基础段落样式；
- `Guide Prompt`：可复制的 Prompt 区块；
- `Guide Code`：普通代码或文本围栏；
- `Guide Bullet`：清单项目；
- `Guide Note`：提示和说明。

需要调整配色、字号或段落间距时，直接在 Word 中编辑模板并保留这些样式名，生成器即可继续复用。不要只改导出的单份文档来代替模板修改。

最终只交付用户所需指南和简短说明，不附模板研发记录、对照作者的私有故事或检查中间产物。生成文件成功与实际成片效果是不同事实。
