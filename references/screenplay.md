# LibTV 剧本创作与修改模块

模块选择与共同协作方式见 [模块总览](../SKILL.md)，只在本次请求涉及剧本创作或修改时使用本模块。

## 1. 本模块只解决一件事

把用户提供的想法、Logline 或大纲发展成有吸引力、人物可信、因果清楚的剧本；用户要求修改时，以现有原稿与修改范围为准。

这是需要创作剧本时的一条分支，不是整个 Skill 的前置关卡。已有想法或大纲可以直接扩写，不要求先补一条 Logline；用户自带剧本且只要分镜、资产或 Prompt 时，直接进入对应工作，不自动重写、评审剧本或要求确认故事方向。用户要求修改剧本时，以其原稿和修改范围为准。

用户仅要求剧本时，直接交可阅读的剧本；剧情节拍是内部组织故事的方法，不是必须让用户逐关审批的表格。分镜、资产和 Prompt 不抢占这一轮；用户明确要求整套制作方案时，结合对应模块一并交付。

用户确认采用这份完整剧本后，或接着说“好，下一步”继续制作时，直接按 [完整制作指南](complete-word-guide.md) 交付一份 Markdown 文件：把确认剧本、分镜、全部必要资产与生成 Prompt、逐镜视频 Prompt、声音与剪辑安排放在一起，不再只输出分镜或询问是否继续。明确要求 Word／`.docx` 时再按指定格式导出；明确的局部请求仍只处理局部。

## 2. 创作规则

接续用户认可的故事方向、已有 Logline、大纲或剧本，以及题材口味、时长和明确偏好，完成本次要求的剧本创作或修改。用户要求仅大纲或仅局部修改时，依该范围处理。

用户指令优先于模板默认值。明确选定的故事不重新选题；明确委托写剧本时，不再逐项询问是否同意大纲、角色和每个场次。普通细节的扩写服从下方总体原则，不借补全改变已定故事。若关键缺口需要新增主线事件、人物或设定，指出缺口并取得用户对该变化的确认，不以标注假设代替同意；其余可确定部分继续完成。

### 已确定故事的推进原则

以下适用于围绕已确定故事写大纲或扩写剧本。尚在自由提案阶段，或用户明确要求另起故事、重构内容时，按其创作范围工作；已有完整剧本仅做制作指南时仍保留原文，不凭本节改写已确认内容。

1. 严格按已确定故事推进，保留主线事件、人物关系与设定，不擅自新增主线事件、新人物或新设定。
2. 先判断人物在当下情境中的正常反应，再写说话、行动与取物。行为来自人物已知信息、目标和处境，不为交代信息突然开口、行动或拿出道具。
3. 所有事件有清楚的原因、经过与结果，行动造成后果，后果引出后续选择，不靠作者解释推动。
4. 每个场景、道具、动作都有可理解的来源和用途，与已建立的情境相连，不凭空出现。来路可以由既有环境与前文自然建立，不要求给每件普通陈设另加一场来历说明。
5. 剧情依靠具体事件和人物选择前进，不用作者总结、解释性旁白或概念化表达代替场面。故事原有旁白可以保留，但不拿它补救缺失的行动因果。
6. 不为悬念硬塞危机；需要集尾钩子时，由本集事件及人物选择自然引出。独立短片仍按已定结局收束，不额外制造续集危机。

### 人物小传先建立行为依据

用户需要人物小传，或开发故事确实缺少人物依据时，整理身份与年龄、影响当前选择的经历、关键关系、正在争取什么、顾虑或底线，以及面对不同对象时的反差。主要角色写清这些联系，次要角色按剧情作用简写；不要求每个路人都有童年、秘密和成长线，也不设小传字数。

已有剧本先提取已有事实，不为了补齐小传新增创伤、亲缘、动机或隐藏身份。普通造型与表演细节可作为制作建议；会改变人物核心关系或剧情的缺口另行指出，不将推测写成已定设定。只有角色图片时提取可见特征，不从脸或服装反推真实职业、性格与人生经历。

小传用来解释人物怎样选择，不只罗列“善良、强势、漂亮”等标签。把性格落实到对谁采用什么态度、受到什么刺激会改变做法；没有事件依据时不强造一个证明性格的新桥段。人物外形、声音和当场表演分别交给 [资产模块的人物衔接模板](assets-sound.md)，不把所有内心设定原样塞进生图 Prompt。

### 人物、节奏与视听表达

内部先理清：人物想做什么，先采取什么行动，行动造成什么变化，因此改用什么办法，最终如何收束。不强制三幕、八节拍、固定场数、悲剧或反转。小愿望、误会、交易、关系进展和动作喜剧都可以构成完整故事。

开场先建立值得观看的具体情境，再按需要释放背景。不要为了开场刺激，给所有题材都加追杀、事故和倒计时。

人物不是设定说明员。让主要角色有自己的观察方式、在意的东西、说话习惯和行动选择；配角也会争取、拒绝、误判或改变主意，不只是提醒主角、被拯救或解释规则。

人物反差要影响选择，而不只是外貌标签：表面守规矩的人在哪件事上愿意破例，嘴上不在乎的人会替谁保留什么。职业习惯、衣着和随身物可以留下辨识点；口头禅、武器和技能只在人物需要时设计。配角从自己的目标出发影响主线，例如店员先要保住工作，主角的请求碰到他的顾虑，双方才改变办法；不按配额塞入路人或让偶然出现的人解决全部难题。

中段要有事情发生并改变处境。重复尝试应带来不同后果、关系变化或新信息，不只换一个场景展示相同失败。高潮和结尾来自已有行动与条件，不临时新增万能规则或强行排除显而易见的解决办法。

节奏也来自情绪对比：紧张中的短暂松弛、尴尬或生活小插曲，可以让人物更可亲，让下一次变化更有力量；是否使用由题材决定，不为喜剧配额打断危险或抹去后果。用户要爽感时，回报应兑现此前的准备、能力和代价；连载集尾的钩子从本集选择的后果长出来，独立短片则允许完整收束，不一律留下新危机。

先分清信息顺序：作者知道什么、人物知道什么、观众此刻看到了什么。反转型故事合理保留关键线索；悬念型故事可以让观众领先人物。不要靠人物忽略眼前事实拖延揭晓。

对白写人物正在做的事：试探、讨价还价、遮掩、逞强、安慰、催促或告别。允许有生活感的停顿和言不由衷，不把每句都打磨成主题金句。动作能自然表达的，不重复解释；需要说清楚的也不故弄玄虚。

画面和声音写成可见、可听的行动：谁先伸手、谁缩回、东西落在哪里、哪个声音让人停下。光影和细节服务情节与情绪；本阶段不填写镜头参数、资产编号、节点和生成语法。

承载转折的道具先有可信来路与当下用途，再参与选择和后果：谁带来、放在哪里、为何会动用，使用后改变了什么。线索可让观众看见但暂不解释，不必把每件日常物品的来历都演一遍。人物取物、进入空间或调用能力，应与此前建立的条件相容；对白、动作、证据各用所长，不把视觉叙事误解为禁止人物通过交谈解决问题。

默认追求最佳故事与成片效果。不要因为用户基础较少，就自动删掉有价值的动作、群像或奇观。把制作挑战留给后续实现方法，而不是偷偷降低创意标准。也不把“克制”“宏大”“虐心”当成所有题材的统一答案。

剧本尚未确定、当前只请求创作或修改剧本时，可在对话中交可读正文：片名与题材、必要的简短说明、完整分场剧本；用户指定文件格式则跟随。确认采用后进入完整 Markdown 指南交付，不继续用零散聊天段落代替最终文件。用户明确要求 Word／`.docx` 时按指定格式导出。未指定时长可给创作建议，不把它说成已测得的实际片长，也不强制所有故事同样长。

交付前围绕当前稿做轻量自查：故事能否被复述，关键行动与世界规则是否相容，信息顺序是否符合预期，对白有没有重复解释，结尾是否由前文长出来。发现明显问题就修正，不展开穷尽式 QA、不默认增加多轮代理审核，不设置固定自查次数、硬秒数或 Token 指标。

用户反馈后，先理解感受与可能原因的区别，再作专业判断；保留其认可部分，修改具体问题。局部反馈优先给可直接替换的段落并说明关联影响，别重写无关场次；用户要求全稿则交回完整更新稿。整段思路被否定时也可换方向，不为了维护原稿持续辩论。

### 总纲与集纲处理同一故事的不同尺度

用户要求多集开发时，总纲写贯穿全剧的关键事件因果与主线走向，集纲展开各集实际发生的场面。以“承接的处境 → 本集人物的行动与选择 → 场面后果 → 自然接续点”作为内部底稿，不把这些标签强制列成每集必填表。每集落实总纲中相应事件，不为了集数平均切割情节或重复拖延同一个误会；已建立的线索按故事安排推进和兑现。

总纲与集纲都沿用下方镜头化文学规范，只调整展开尺度，不退回抽象的情绪总结。只要某集、分镜或资产时，就处理该范围，不先补全季集纲；已有分集稿不擅自重排事件或给每集加新危机。

### 镜头化文学大纲写作规范

用户要求大纲时，按以下规范直接交可阅读正文；不因此给仅要剧本或局部修改的用户增加大纲关卡。用户明确指定其他大纲形式时按其最新要求执行。这里的“镜头化”指可被观看、可转成分镜的场面，不是提前填写摄影参数或逐镜表。

1. 大纲写成镜头化文学大纲，不写成分析稿、设定说明书或仅概括主线的故事梗概。
2. 用画面、动作、物件、空间、声音、身体反应和场面后果呈现故事。
3. 可概述谁告诉谁什么、谁质问谁什么、谁宣布什么，不展开完整台词；正式对白留到剧本阶段。
4. 正文不写“这说明”“这象征”“这代表”“观众看到”“完成某功能”等作者解释。用户确需设计理由时另列说明，不混进大纲场面。
5. 画面只写实际存在、发生的内容，不写“没有血”“不是这样”“并非如此”等否定式画面。将缺失线索转成可见证据，例如用“门锁断口平整，碎屑落在门内”表达异常，而不是用一串排除句代替画面。
6. 不以“他们开始调查”“两人关系变好”“众人陷入危机”概括推进，写出具体做了什么、遭遇什么回应、留下什么后果。
7. 重要信息通过冲突、证据、行动或选择自然暴露，不把角色写成世界观讲解员；人物交流也应有当下目的和作用。
8. 每段场景有明确位置感，写清人物从哪里到哪里、道具从何处出现及空间移动，让读者能想象行动路径。
9. 大场面不只写气氛，写清谁在做什么、谁阻止谁、谁因此被迫改变行动。
10. 场景不贪多，每场围绕一个清楚的剧情任务组织行动；避免为堆气氛换地点，或把互不相干的任务塞在一起。

可用“地点与当下处境 → 人物行动 → 回应或阻力 → 场面后果”组织段落，不把这几个标签强制显示给用户。

### 大纲正文禁用表达

**适用范围：新写或修改的镜头化文学大纲正文。** 本版保留用户确认的严格清单；它不是所有题材、对白、提案或日常沟通的通用词表，也不覆盖用户明确指定的其他大纲形式。执行目标是让场面可见，而不是机械搜词或把“终于意识到”换成另一个抽象总结。

在镜头化文学大纲正文中执行以下完整清单，不只作为可忽略的建议。“发现”禁用项特指以该词概括推进；其余所列词语与句式在正文中避用。改写时补具体行动、证据或反应，而不是换一个同义总结词。

1. “第一次”
2. “终于”
3. “意识到”
4. “明白”
5. “发现”用于概括推进
6. “学会”
7. “成长为”
8. “代表着”
9. “象征着”
10. “说明了”
11. “命运开始”
12. “更深的黑夜”
13. “所有人都知道／所有人都明白”
14. “这一刻他们还不知道”
15. “空气里弥漫着不祥的预感”
16. “刚才的选择会把他们推向……”
17. “接下来等待他们的是……”
18. “危机才刚刚开始”
19. “不会……只……”及同类句式

本清单与正向画面规则用于大纲正文，不用于删除已确认剧本的原台词、来源引文或本模块标明的反例，也不混同导演分析、日常沟通和生成 Prompt 的约束写法。Prompt 为控制画面所需的否定约束仍按 Prompt 模块处理。交付前结合原有轻量自查顺手修正正文，不新增评分、审批或多轮审核。

例如：大纲中的“她终于明白对方在等她”应落实为“她拉开门，对方提着已凉的晚餐站在楼道里；她接过饭盒，侧身让出门口”。已确认台词“你终于来了”则原样保留。这是限定作用范围，不是放宽大纲标准或借改词新增主线。

## 3. 默认交付结构

```text
《片名》（题材 × 情绪或视觉特色）
建议时长或用户指定时长

本稿采用的关键扩写（仅在确有必要时简短写明）

完整剧本
场景一｜地点｜时间
具体行动与必要环境
人物姓名：对白
必要的声音或停顿

场景二……
直到本次请求范围内的结局

一个邀请反馈的问题（需要用户审稿时再问）
例如：哪一段让你想快进，或者哪个人物的反应不像真人？
```

导演说明和角色卡不作为每次必交的大章节。用户需要看设计依据时再展开；需要分镜、资产或视频 Prompt 时进入对应模块。

## 4. 审稿提示

- 不靠世界观说明，是否能看懂眼下发生了什么？
- 中间是否有想看下去的变化，而不只是等待结尾答案？
- 人物是在争取自己的东西，还是替作者解释主题？
- 结尾是否让前面的行动有结果，情绪是否符合用户想看的题材？

这些是审稿提示，不是评分表。最终审美判断交给用户；结构完整、逻辑检查过，都不等于已经写得好看。

## 5. 自写示例：把“关系改变”写成一次选择

**概括写法：**店员发现老人值得帮助，终于放下顾虑，两人的关系变好了。

**可视化大纲：**收店时，店员把留给自己晚餐的最后一个面包装进纸袋。老人推门进来，数了两遍掌心的零钱。店员指向价签；老人收钱准备离开。店员拿出已经装好的面包，撕下一半放回自己的餐盒，把另一半递给老人。老人接过，替腾不出手的店员扶住卷帘门。

这里先交代面包的归属，让帮助有具体代价，再让接受帮助的人主动回应；不补一段善良宣言，也不把老人只写成被救助的对象。这是写法示例，不是所有故事都要温情结尾或无对白。
